# Правила разработки для ИИ-агентов

Этот файл обязателен для любого ИИ-агента, который вносит изменения в AlphaLauncher. Перед изменениями прочитайте ARCHITECTURE.md.

## Общие принципы

1. **Слои не нарушаем.** `core/`, `auth/`, `settings/`, `minecraft/`, `services/` не импортируют PySide6 и не импортируют `ui/`. Всё, что касается окон, — только в `ui/`.
2. **Синхронный код ядра, асинхронность в UI.** Новые операции с сетью или диском пишутся как синхронные функции в сервисах. `ui/` запускает их через `TaskRunner.run(...)`. Не вызывайте сеть из обработчиков кнопок напрямую.
3. **Без заглушек.** Каждая кнопка и пункт меню должны выполнять реальное действие. Если функция не реализована, не добавляйте кнопку.
4. **Минимум зависимостей.** Новые пакеты добавляются только при крайней необходимости и только в `requirements.txt`. Сеть — через `core/http.py`, а не через сторонние библиотеки.
5. **Не раздувайте файлы.** Один модуль — одна ответственность. Если файл перевалил за ~300 строк, выделите часть в новый модуль.
6. **Имена говорят сами за себя.** Функции — глаголы (`install_version`, `build_launch_command`), классы — существительные. Русские строки пользователю, английские идентификаторы в коде.
7. **Не дублируйте код.** Если логика нужна в двух местах, вынесите её в `core/` или в соответствующий модуль.

## Стиль

- Каждый файл начинается с однострочного docstring на русском языке.
- `from __future__ import annotations` в каждом модуле.
- Аннотации типов обязательны для публичных функций и методов.
- Ошибки, которые видит пользователь, — подклассы `LauncherError` с текстом на русском языке. Внутренние ошибки логируются через `logging` и показываются общим сообщением.
- Не используйте `print`. Для диагностики — `logging.getLogger(__name__)`.
- Не используйте localStorage-подобные хранилища. Постоянные данные — только через `SettingsStore`, `AccountStore` или `write_json_atomic`.

## Чего нельзя делать

- Нельзя сохранять пароли. Microsoft-вход использует только OAuth-токены.
- Нельзя писать в папки вне `ROOT` (кроме выбранной пользователем папки игры).
- Нельзя скачивать файлы без проверки SHA-1, если манифест её предоставляет.
- Нельзя менять `MS_CLIENT_ID` и `MS_REDIRECT_URI` без явного указания пользователя.
- Нельзя удалять пользовательские данные (`data/`, папка игры, `mods/`) без подтверждения в UI.

## Проверка перед сдачей изменений

1. `python -m unittest discover -s tests -t . -v` — все тесты зелёные.
2. Для изменений в `ui/` — `python -m py_compile` всех файлов и запуск `python main.py` на Windows.
3. Если изменилась логика запуска или установки — добавьте тест в `tests/test_launcher.py`, используя локальный HTTP-сервер или подменённые функции.
4. Обновите ARCHITECTURE.md, если добавили модуль или изменили поток данных.

## Добавление функций

- Новая страница: см. раздел «Расширение» в ARCHITECTURE.md.
- Новый источник версий, загрузчик модов, новый тип аккаунта: сначала опишите интерфейс в docstring модуля, затем реализуйте.
- Поддержка новых правил Mojang: только в `core/rules.py`.
